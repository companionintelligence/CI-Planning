# Tasks, habits, routines, and objectives

## Capture a task

1. Search first if the user might mean an existing task. Include relevant status/archive filters and the intended owner-local date.
2. For a quick capture, use the app's **Add** action / quick-add and enter the user's wording. For structured fields or a non-task item, use the matching Tasks tab and editor.
3. Use bulk add only when the user provides multiple items or explicitly asks to import a list.
4. Inspect the parsed title, date, time, estimate, recurrence, direction/category, and objective before saving. Preserve ambiguous language as notes or ask rather than inventing a deadline.
5. Verify the new row/card and any inferred date or placement.

## Edit or complete

- Use the task's own card/menu/editor. Preserve unspecified text and metadata.
- Completion may update linked time blocks, a Today focus slot, objectives progress, and a close-ritual prompt. Complete only the selected task; treat any follow-up ritual as optional.
- Rescheduling a recurring task may offer **this instance** or **this and following**. Choose the exact scope expressed by the user; ask if not clear.
- Archive is for removing completed/old work from active lists. Cancellation/throw-away is not the same as archive. Check the visible action label and effect.
- A task's “delete” route normally soft-cancels it and retains history. Confirm the exact matching item before using it.

## Task sections and tabs

- **Tasks** includes the open backlog, **New Today**, **Scheduled**, and email suggestions that wait for approval. Calendar, memory, and text suggestions may already be promoted as ordinary tasks; do not duplicate them.
- **Habits** shows recurring habit work and streak context. Completing a habit instance may reset according to its recurrence rather than archive it.
- **Routines** groups routine tasks and supports staging/placement when enabled. Use the Flight Plan review before committing a staged schedule.
- **Timeblocks** manages reusable time-block/task groupings; distinguish a timeblock template from a dated calendar block.
- **Archive** exposes completed, archived, and cancelled work with separate views/filters; verify current filter before restoring or changing an item.

## Objectives

- Navigate to the **Objectives** Tasks tab or board. The hierarchy is Goal → Project → Objective; a leaf objective can link tasks and display progress rolled up from linked work.
- If the user asks for a milestone, determine whether they want an Objective or an ordinary Task. Objectives describe outcomes; tasks describe actionable steps.
- When creating a subtask under an objective, use the parent objective's add-task control. When creating an objective, keep its parent level explicit and preserve existing hierarchy.
- Validate progress after completing/adding linked work. A blank/unknown progress value is not equivalent to zero percent.

## Tags and categorization

- Direction/pattern tags scope availability, filters, reminder preferences, and scheduling windows. Categories are separate task classification labels. Do not interchange them.
- When changing a tag, verify both its name and resulting color/icon. Before deleting, inspect whether other tasks, availability, or preferences depend on it; honor the UI warning.
- Use the app's tag suggestion or auto-tag affordance only when requested; review before accepting bulk changes.
